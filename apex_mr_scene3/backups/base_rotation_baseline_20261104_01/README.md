# apex_mr_scene3：双 UR5 连续轨迹装配

本场景用两台 UR5 搭建带收口挡板的积木连桥，研究临时支撑的布置、承载交接、机械臂释放和最后撤撑。旧工程位于同级 `apex_mr_scene1`。当前主场景已更新为通过完整动力学验收的连续运动版本。

## 优化怎样执行

1. 当前几何资格检查和 MILP 正常求解。已知完整参考的支撑方案与当前无约束最优目标值相同，作为平局优先选择；其全部任务、抓取变换、原始端点和依赖保持闭合。
2. 固定原端点精化 6 条有绕行的路径。旧路径先按当前完整几何上下文重新检查，再与有界 RRT-Connect / shortcut 候选比较，选更短有效路径。95 条已是直线或零位移的运动不重搜 IK。该策略避免局部较近 IK 分支破坏后续可达性。
3. 共线片段共享一条五次时间曲线。小角度滑动采用经几何与末端走廊复核的 C2 Bezier 曲线。所有外部依赖在连续段入口取得，原始任务守卫保留，节点由实测进度确认。
4. 以新曲线重新构建全相位跨臂冲突，再检查完整名义时序与等待位姿，最后执行真实关节动力学并独立审计。

6 个宏通过 1317 个真实机器人/载荷配置检查和 2629 次 FK 检查。最大末端偏离约 0.0588 mm，低于 0.5 mm 走廊上限；完整名义时序的 5589 个样本全部通过。依据见 [曲线验证](results/apex/curve_smoothing_validation.json) 和 [独立曲线审计](results/smooth_motion_candidate/independent_curve_audit.json)。

命令轨迹采用原有 `vmax=0.6 rad/s`、`amax=1.2 rad/s²`，新增 `jmax=8 rad/s³`。这些是命令曲线解析上界；位置伺服和接触动力学的实测速率并不自动满足同一 jerk 上界。实测不等间隔差分的 jerk 峰值估计仍约 A/B 13.30/11.46 rad/s³，不能宣传“实际 jerk 小于 8”。

## 场景中的问题

左塔上的临时连接已定位桥面，但尚不能独立承担桥面载荷，A 臂在桥下持续扶持。右侧永久塔的上层块 K1 和锁桥砖 K2 存放在左侧料区，设计上需要 A 供料；B 负责支撑工具与后续装配。A 如果一直扶着桥面，就无法拿到这些砖。

B 可以放入一个带配重底座的 C 形支撑架，确认它接替载荷后让 A 离开。A 取 K1、K2，经共享暂存区交给 B；B 从侧面装入 K1，再安装 K2，使永久承载结构闭合。最后要卸载支撑、将支撑运回工具位，并完成前挡板收口。

支撑位置会影响可选顺序。桥腹内部的位置可以承载，但前挡板闭合后，侧墙、后墙和挡板可能把支撑围住。靠前的位置保留外侧抽出通道。规划器应比较这些选择，而不是把“放进去以后结构暂时不倒”当作任务完成。

“只有 A 能取料”目前是工作站布置的设计约束：两臂基座位于左右两侧，K1、K2 料位到 B 侧较远。尚未完成所有抓取姿态、关节限位和碰撞条件下的 IK 可达性验证，不能把平面距离估算当成不可达证明。

正式规划器会在有限候选、IK 初值、采样时间和重试次数内检查资格；日志中的失败表示本次有界搜索未找到合格解，不是目标整体不可达或不存在可行路径的证明。A 专属供料限制同时属于当前任务模型的显式输入。

所有长度单位为米，质量为千克，力为牛顿。下表列出正式动态场景的当前参数；采用放大的模块化积木尺寸，不代表真实 LEGO 卡扣或实机工具设计。

| 项目 | 名义值 |
|---|---|
| 桌面 / 底板顶面 | `z = 0.760 / 0.772` |
| A / B 基座 | `[-0.70, 0.13, 0.783] / [0.70, 0.13, 0.783]` |
| 桥面中心 / 尺寸 / 质量 | `[0.04, 0.20, 1.032] / [0.52, 0.16, 0.04] / 0.45` |
| 左塔 / 初始桥面连接 | 塔中心 `x = -0.28`；前缘铰链 `x = -0.22`，动态被动转动副的名义制动力矩 `0.35 N·m` |

| K2 动态质量 | `0.14 kg`，纳入正式候选的保守支撑载荷筛选 |
| 共享暂存区 | `x = 0, y = -0.36` |
| 支撑底座 | 尺寸 `[0.14, 0.28, 0.012]`，配重质量 `2.0` |
| 支撑鞋 | 尺寸 `[0.10, 0.22, 0.012]`，相对底座沿局部 Y 偏置 `0.10` |
| 动态支撑鞋行程 | 当前配置伸出 `0.010`，永久承载验证时回缩至 `0`；物理执行器范围 `0–0.012` |
| 拆卸前卸载 | 通过实测承载转移和 `10 mm` 回缩后再水平抽出；历史预览为 `8 mm` |

初始桥面自重在左侧连接处产生约 `0.45 × 9.81 × 0.26 = 1.148 N·m` 力矩，超过设计中的 `0.35 N·m` 临时连接限值。这是场景中“持续扶持有必要”的名义依据；实际连接及支撑仍需建模和验证。

在 `8 N` 插装工况下，同时计入动态版 `0.14 kg` 的 K2 自重，忽略临时连接和已接触永久塔可分担的载荷，支撑反力的保守平衡估计为下式。两个候选统一采用较短的 `x = 0.06` 支撑力臂计算载荷要求；外侧虽然已移到 `x = 0.08`，仍沿用这个保守要求。

```text
R × (0.06 - (-0.22))
  = 0.45 × 9.81 × (0.04 - (-0.22))
    + (8 + 0.14 × 9.81) × (0.24 - (-0.22))
R ≈ 19.498 N
采用 1.5 倍设计系数时，所需承载能力至少约 29.248 N。
```

此公式与正式编译器的候选载荷筛选一致；历史纯离散基线保留原先未计入新版 K2 自重的假设，不作为动态版的承载验收依据。这只是指定载荷下的准静态筛选。配重抗倾覆、接触压力分布、摩擦、工具抓取、结构变形、连接强度、插装冲击和实际卸载过程都不能由这一条公式替代。支撑架属于带回缩机构的假设工具，尚未完成实物机械设计验证。

## 支撑位置与完整生命周期

| 候选 | 底座参考位置 / 朝向 | 当前判据与顺序影响 |
|---|---|---|
| `outer_front` | 动态版 `[0.08, -0.05, 0.772]`，鞋沿 `+Y` 偏置 | 与 A 手掌保留名义 X 间隙，并在挡板外侧保留取出通道 |
| `inner_pocket` | `[0.06, 0.26, 0.772]`，旋转 180°，鞋沿 `-Y` 偏置 | 内侧支撑；允许先拆支撑再关挡板，关挡板后会受围挡限制 |
| `weak_narrow` | Y 位置 `-0.085`，其余沿用前侧候选 | 与桥面投影仅约 `5 mm` 重叠，低于 `10 mm` 设计门槛 |

前挡板中心位于 `y = 0.105`，两侧墙位于 `x = -0.035 / 0.155`，后墙位于 `y = 0.43`。这些围挡用于构造可检验的拆除通道差异。本轮完整实际验收覆盖外侧支撑的放入、装配、卸载、持物抽出和运回；其他候选仍需各自的路径与动力学执行证据。历史静态预览与抽象基线保留原外侧 `x = 0.06` 的位置，与当前正式动态候选分开记录。

枚举器比较三个候选以及“关挡板前拆除 / 关挡板后拆除”两种顺序，在当前离散模型和设定代价下选择可行方案。拒绝原因应随结果保存。**内侧支撑在关挡板之前可拆除时属于有效候选**，不能仅因最终闭合几何会围住它就提前排除。

程序的代价是用于比较候选的假设数值，不是仿真计时、UR5 执行耗时或实测效率；有限候选中的最小代价也不等于连续任务与运动规划的全局最优解。

本次枚举还比较 K1 / K2 的供料顺序，共检查 12 种组合，3 种满足当前符号约束，9 种被拒绝。选中外侧支撑与 K1→K2 供料；外侧支撑在封板前后拆除的名义代价相同，程序用固定平局规则选中封板后拆除。详见 `results/lifecycle_plan.json`。

## 如何接入 APEX-MR

[APEX-MR 原文](https://arxiv.org/html/2503.15836v2) 的主线是分配任务及抓取/支撑方式、生成顺序参考运动、构造多模态时间计划图并依照事件执行。本场景沿用这一接口方向，下列模块已共同完成上述运行的实际验收。

| 层次 | scene3 需要表达的内容 | 当前状态 |
|---|---|---|
| 任务与状态 | 已装部件、机械臂持物、支撑提供者、支撑位置、挡板状态、工具是否归仓 | `apex/scene.py` 和 `compile.py`；另保留离散基线 |
| ILP 或时序任务规划 | 分配安装/供料动作，选择支撑位置及占用区间，安排拆除时点 | `apex/allocation.py` 的 ILP 与几何失败反馈；本轮选择外侧支撑、先拆撑后关挡板 |
| 运动规划 | 含支撑工具和变化装配几何的 IK、抓取、侧向插入、撤离和双臂避碰 | `apex/motion.py` 与 Lua 后端的真实 RRT-Connect 查询 |
| 多模态 TPG | 同臂顺序、共享区域冲突、载荷转移和永久承载验证的事件边 | `apex/tpg.py` 生成路径片段及 Type-1/Type-2 依赖；`geometry.py` 检查名义执行 |
| 执行与验收 | 动态伺服、实际仿真载荷转移、卸载、拆除及结果日志 | `controller.lua / runtime.py` 与独立 `validation.py`；本轮完整实际验收通过 |

执行器与验收器检查以下事件约束：

```text
放置支撑 → 验证载荷转移 → A 解除扶持 → A 取专属料区积木
永久连接完成 → 验证独立承载 → 支撑鞋回缩卸载 → 抽出支撑 → 工具归仓
选择内侧支撑时：抽出支撑 → 关闭前挡板
```

“支撑到达指定位置”不能直接触发 A 松手；“K2 到达目标位姿”不能直接允许拆撑。需要相应承载观测与稳定判据。支撑仍受载时禁止直接水平拖出；物体已经出桥下也不等于支撑已归仓。

新流水线在旧工程模块基础上增加工具支撑资源、持续承载区间、载荷转移和回收语义。新的路径、TPG 和实际载荷必须针对场景 3 重新生成并验证；旧日志不作为新场景证据。
