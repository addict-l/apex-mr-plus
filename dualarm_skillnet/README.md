# 双臂积木技能网络规划器

独立的 Python 3.11 规划项目，仅使用标准库。规划器从任务、参数化技能库和三值能力表中推导步骤与双臂时间表，不连接仿真器或大模型，不访问网络。

规划层版本为 v1.2.1；v1.3 仿真接入的进度、坐标约定和验收证据见文末“v1.3 修订”。此前各版本部分保留为历史实现与验收记录。

所有命令都在本目录 `D:\APEX_MR_Plus\dualarm_skillnet` 下运行。

```powershell
python -X utf8 -m unittest discover -s tests -t .
python -X utf8 -m skillnet network
python -X utf8 -m skillnet run tasks/s1_reach_handover.toml
python -X utf8 -m skillnet run tasks/s2_tower.toml --no-proposal --no-prune
python -X utf8 -m skillnet prompt tasks/s2_tower.toml --mode with_capabilities
python -X utf8 -m skillnet all --out out
```

`run` 会打印中文报告，并写入 `out/<任务名>/report.md`、`plan.json`、`taskgraph.mmd`、`taskgraph.json`。`network` 写入 `out/skill_network.mmd`。使用 `--out` 指定项目内的其他输出目录；`run` 与 `network` 可以用 `--skills` 选择技能库。

命令退出码：成功为 `0`，规划未解决为 `1`，输入或文件错误为 `2`。

## 离线增量恢复

先用 `run` 保存正常方案，再用 `recover` 从停稳后的完整符号快照生成剩余计划。例如在中央积木任务开始前，A 臂的放置技能失效：

```sh
python -B -m skillnet run tasks/s1_nearest_arm.toml
python -B -m skillnet recover tasks/s1_nearest_arm.toml --nominal out/s1_nearest_arm/plan.json --snapshot out/fault.json --compare > out/recovery.json
```

第二条命令使用以下 `out/fault.json`：

```json
{
  "state": [
    "arm_at(A, home_A)", "arm_at(B, home_B)",
    "free(A)", "free(B)", "at(red, stock_c)", "empty(board_c)"
  ],
  "disabled_skills": {"A": ["place"]}
}
```

`capabilities` 可选，用事实字符串映射到 `VALID`、`INVALID` 或 `UNKNOWN`，例如 `{"reach(A, board_c)": "INVALID"}`。`completed_steps` 可选，使用原 `schedule` 的零基索引缩小修补范围。实际完成状态由 `state` 提供。`protected` 可选，列出搜索中必须保护的事实。

恢复器建立能力和技能到候选动作的索引。它先用旧计划的剩余动作、换臂候选和一层前置条件的提供动作找可行解，再在全部可用动作中做分支限界。比较结果包括首解搜索时间、扩展数、最终剩余工时和最优性界。进程内可保留 `skillnet.planning.recovery.RecoveryPlanner` 以复用动作网和索引。独立的命令行调用从 TOML 建索引，从 `plan.json` 读取旧计划，准备时间单列为 `preparation_seconds`。

当前入口做符号恢复，快照使用任务中已登记的对象和位置。运动验证、在线状态采集和 TPG 切换由后续仿真接入处理。

## 输入格式

技能库位于 `skills/blocks_v1.toml`，所有任务共享同一份九技能定义。参数类型为 `arm`、`block`、`loc`、`slot`，`pre` 允许否定条件，`add` 在结束时生效，`delete` 在开始时生效。技能网络从效果与前置条件自动生成，推导条件通过领域声明的基础谓词连线。

任务放在 `tasks/*.toml`，可以复制示例后仅修改输入。顶层 `name`、`description`、`arms`、`goal` 和 `fill_all_slots` 必须写在第一个表之前。`[[arm]]` 提供初始三维坐标与速度，`[[location]]` 提供位置坐标与类别，`[[block]]` 用 `at` 或 `installed_in` 指定初态，`[[slot]]` 定义类型与上下连接。

`[capabilities.reach]` 和 `[capabilities.liftable]` 可以使用 `default = "VALID"`、`"INVALID"` 或 `"UNKNOWN"`。显式条目支持 `valid = { A = ["board_l1"] }` 或 `valid = [["A", "board_l1"]]`。未声明的能力为 UNKNOWN。可选的 `[proposal]` 中，`steps` 是动作字符串列表，`instruction` 是任务说明；省略此表会直接搜索。

默认目标要求所有臂空闲、所有非临时槽位装好、所有临时槽位清空，再加上 `goal` 中的条件。设置 `fill_all_slots = false` 可以关闭非临时槽位的自动目标。详细字段见 [SPEC.md](SPEC.md)。

## 搜索结论

| 结论 | 含义 |
|---|---|
| `solved` | 找到方案，且通过当前运动后端验证 |
| `no_plan` | 完整搜索耗尽且未遇到未知能力 |
| `unknown` | 未验证能力或运动验证未知使结论无法确定 |
| `budget` | 搜索预算或反馈轮数用尽 |

耗时由欧氏距离、臂速与操作时间组成；总 cost 是双臂完成时间。默认运动后端只是占位验证，不代表真实几何可行性。`ScriptedBackend` 可以模拟一次运动失败或能力验证，用于检查反馈回路。

## 实现说明

- 动态状态只保存基础动态事实；静态事实由引擎统一检查，推导条件交给领域实时计算。
- 同类型参数必须绑定不同对象；技能参数顺序使用 TOML 的声明顺序。
- 能力表显式条目覆盖默认结论，未声明的能力谓词返回 UNKNOWN；同一事实在输入中声明多个不同结论会报错。
- 动作开始时删除事实，结束时添加事实并更新臂的位置；持物和托举通过缺少 `free` 表示持续占用。
- 搜索按（累计耗时、偏离参考方案的次数、入队序号）排序。普通事件时间保留 9 位小数，避免浮点减法使同一事件状态无法去重；独立的极小正耗时保留有效数字，不会截断成零。整秒累计时间上的亚纳秒差异仍受此精度限制。
- 加载器也会拒绝初始状态已经违反稳定规则的任务；自动生成的 `home_<arm>` 同样参与全局 id 唯一性校验。
- 补全子计划先按开始时间顺序回放，通过全部前置、能力、稳定检查才接纳；若并行子计划不能按此顺序安全串行化，会记录原因而不输出不可执行的顺序方案。
- 参考方案仅影响相同耗时方案的优先级，不固定最终臂分配；模型返回的 `goal` 仅作为提案信息，任务文件的目标始终是验收依据。
- `max_model_rounds` 是初次分解之外允许的反馈重试次数。规则层已修好的方案不会再反馈给分解器。反馈轮数耗尽而仍需搜索或运动验证时，返回 `budget`。
- 示例只保留各任务需要的位置；塔的三层使用互相匹配的独立积木与槽位类型。没有力学计算、模型调用、仿真器连接或真实轨迹生成。
- 两个较大的支撑示例附带可执行的可选 proposal，用于演示顺序方案如何重新分配、并行排序。它们和其他任务共用同一技能库与规划算法。

### 大场景搜索实现

大动作空间会先在一个受限参考集合中运行小预算 UCS，取得经完整规则检查的可行完成时间上界；参考集合优先使用补全方案。这一步失败时仍运行完整搜索。最终 UCS 的动作集合与排序规则保持不变，只在“当前耗时＋可证明的剩余耗时下界”已超过可行上界时裁剪。参考搜索和最终搜索共享原有 20 万扩展、60 秒预算；参考集合不限制最终选择，较差的参考方案也不能排除更快的方案。

下界结合忽略删除和资源冲突的事实传播，以及适用于原版积木技能的抽象状态图。抽象图合并具有相同可达臂集合的位置、放宽空位限制，保留槽位连接和稳定性；用位置类之间的最短距离估计移动，分别计算各臂与结构互斥资源的最少剩余工作量并取最大值。运动中的动作按立即完成放宽，再保留真实剩余执行时间下界。下界的操作时间保守扣除数值舍入裕量。不兼容领域、自定义 cost、构建预算不足或未覆盖状态不会使用该抽象下界。相关实现位于 `planning/bounds.py` 和 `planning/abstraction.py`，有未裁剪 UCS 对照和反例测试。

当抽象图足够小时，还构建以 0.5 秒为单位的事件抽象图。动作最短时长向下取整，达到该时长后允许继续占臂等待结束，也允许就绪动作同时结束，因此能够保留真实动作的因果与稳定顺序。这只是额外的剩余耗时下界，最终时间表仍使用原始距离模型与事件状态 UCS。抽象图超过构建预算时回退到较弱的安全下界。

## v1.1 修订

本轮按 `FIX_v1.1.md` 完成，保持 `SPEC.md`、修订单和项目外文件不变。只使用标准库，未执行 Git 操作或访问网络。核心变化是让系统在没有 proposal 时自行搜索托举、临时支撑及清理步骤。

### 搜索与最优性

`planning/search.py` 的主搜索改为事件状态 A*，优先队列严格按 `(g + h, 偏离 hint 次数, 序号)` 排序。`g` 仍是实际累计完成时间，动作耗时仍由开始前的 `arm_at`、欧氏距离、臂速和操作时间计算，开始删除、结束添加、资源互斥和稳定性规则均沿用 v1。

新增 `planning/heuristic.py` 统一构造启发值，供正式搜索和可采纳性测试共同调用。无论是否存在 proposal 或可行上界，主搜索都会使用启发值。它取以下保守下界的最大值，而非相加：

1. **事实传播下界 HMax**：忽略删除、否定前置和资源冲突；同一动作的肯定前置取最晚可达时间，不同生产者取最早时间。操作只使用保守操作时间，不计移动。积木领域的推导条件按其 AND／OR 关系传播，稳定规则中的锚定与支撑也作保守放宽；插装臂不能被同时当作自身的托举臂。负目标取必要删除和同臂恢复的最短时间，多个目标取最大值。执行中动作的效果按立即可用放宽，再保留真实剩余时间下界。这些放宽均不会使真实可行方案变慢。
2. **工作量抽象图**：沿用 v1 的 `PatternDatabase`，合并具有相同可达臂集合的位置、忽略 `empty`，保留槽位连接与稳定性；槽位和初始臂位置分别保留。位置类间移动取任意两点的最短距离。对各臂和结构互斥资源分别求到目标的最小剩余工作量，再取最大值。每个真实动作都有抽象对应；每种资源在实际方案中都不能同时执行两步，因此其剩余总工作量不超过实际剩余完成时间。
3. **事件抽象图**：当工作量抽象图不超过 1,000 个状态时，尝试构建 `EventPatternDatabase`，时间步为 0.5 秒。动作最短时长向下取整；达到最短时长后可以继续占臂等待结束，可以选择同时结束多个就绪动作。将真实方案的绝对开始、结束时刻都向下映射到时间格，动作至少获得其抽象最短时长；等待结束机制允许保留原来的因果顺序和稳定性检查，所以抽象最短时间不会超过真实最短时间。

工作量和事件抽象图查询时免费完成当前执行中的动作，再查询对应空闲抽象节点，同时保留真实最大剩余时间。此放宽只对经过兼容检查的原版九技能与积木领域启用：结构动作互斥，其他动作提前添加效果只会提前提供事实；真实方案按原事件顺序能映射到放宽图。自定义 cost、不兼容技能、未覆盖状态或抽象构建超预算时不使用该抽象下界。构建预算失败时仍可用其余安全下界，最弱可退化为零。保留 v1 的数值精度和保守操作时间舍入裕量。

可采纳下界的最大值仍然可采纳，因此 A* 弹出的第一个空闲目标具有最优完成时间。启发值不要求一致：重复状态仍保存最小 `(g, 偏离次数)`，更低代价的路径会重新入队，没有永久关闭集合阻止重开。新增测试覆盖了不一致但可采纳的启发值、无上界时的启发排序，以及 hint 不能覆盖更优 `g+h` 的情况。

有非空 hint 时，保留受限参考 UCS 来获取真实可行上界：它使用相同的能力、cost、约束和稳定检查，参考失败不会限制主搜索。只在 `g+h` 严格超过可行上界及数值裕量时剪枝。**无 hint 时跳过参考搜索，直接运行 A***。抽象构建、参考搜索和主搜索的时间统一计入默认 60 秒预算，参考与主搜索共享 20 万扩展预算。

本轮没有新增同刻动作排序压缩、支配剪枝或禁止中转位置等动作删减规则，避免未经证明的最优性损失。保留原有的完整事件状态去重：事实集合（含臂位置）和执行中动作及其剩余时间相同时，其后继与未来 cost 相同，只需保留累计代价较小的路径。原有相关动作剪枝及失败回退机制保留，最优性对照直接使用不受该剪枝限制的 `search(engine)`。旧测试中“两次内部调用”等实现细节断言已替换为相同的最优性、约束传递和共享预算行为断言。

基本 `_search(engine)` 默认仍为无启发、无上界、无相关动作剪枝的事件 UCS，作为独立对照；新增私有 `observer` 和 `initial_running` 参数，仅用于采集完整展开节点和从执行中节点续搜真实剩余最短时间。

### 模型接入方式

`skillnet/decompose/ollama.py` 提供 `OllamaDecomposer(model, host, timeout, temperature, seed, mode, max_retries)`。默认模型为上述 Qwen 标签，timeout=120 秒、temperature=0、seed=1101；使用 `/api/generate`、非流式和 JSON schema 的 `format` 约束，num_ctx=8192、num_predict=2048。只使用标准库 `urllib`，禁用请求代理与重定向；本轮 host 参数只接受授权的 `http://127.0.0.1:11434`，其他地址会在发请求前以中文拒绝。

解析失败会把具体原因加入反馈，最多重试 2 次（初次加重试最多 3 次请求）。服务未启动、HTTP/API 失败或重试耗尽时，pipeline 记录中文原因，清空有效模型方案和补全 hint，退回不使用模型直接规划；任务文件中的固定 proposal 不会被误当作此次真实模型输出。初次分解和规则层反馈后的再次分解都覆盖该回退。

适配器保留每次调用的模型、模式、完整提示词、长度、原始输出、原始 API 响应、耗时、重试序号、解析状态和 API token 统计。pipeline 返回 `model_calls`、`model_goal_comparison`、`model_error`；中文报告概述对比与失败，`plan.json` 保存完整记录。

所有 11 个任务增加顶层 `instruction`，只描述目标，不透露臂的可达范围、交接、托举或搭台解法；两个带 proposal 副本与原任务使用相同指令。提示词优先使用它，缺失才回退 `description`；提供 instruction 时不再输出旧 description 或 proposal.instruction，避免在 minimal 模式泄漏解法。两种模型实验提示词的差别只有能力摘要。

`compare_model_goals` 只作对照：比较全部顶层显式目标的覆盖，记录遗漏、多余、未知对象、未知谓词、参数类型或相反条件等错误。模型 goal 永不替代 `Problem.goal`。默认的 filled/free/临时清理目标仍是任务要求，合法默认目标不算多余；没有顶层显式 goal 的任务属于真空覆盖，不能将其 covers_explicit=True 理解成模型覆盖了所有默认目标。

### 自然语言设置与目标指标

新增 `build_prompt(..., mode="nl_only")`，给模型任务指令、场景、技能和能力摘要，要求自行在 goal 中写出目标条件；不提供 `任务目标：`、任何目标事实列表或默认目标说明。格式示例仅给空数组结构，不再放具体目标事实。对 11 个任务的目标替换测试表明，nl_only 提示词不依赖 `Problem.goal` 或显式目标；原 minimal／with_capabilities 的 22 份对照提示词 SHA256 保持不变。

审查发现规则层反馈也可能泄漏 oracle 目标，因此 nl_only 的后续模型反馈只给通用的重新理解指令；解析重试只给 JSON／提案结构／条件语法错误类别，不回显具体条件。完整原错误仍保留在调用记录中。新增测试直接核验模拟服务收到的请求，原两种模式的详细反馈行为保持不变。

目标比较使用**完整任务目标**，即显式目标加默认目标，绝不以模型目标替代验收目标。新增指标定义为：

- `goal_recall`：规范化完整目标集合中被正确模型事实覆盖的比例。
- `goal_precision`：正确覆盖数，除以去重后的全部可解析预测事实数与不可解析条目数之和。错误但可解析的预测也在分母中，不会因丢弃错误而虚高；重复的可解析事实只计一次。
- `goal_invalid`：逐原始条目统计无法解析、未知谓词、对象不存在或变量未代入的次数。同一条目有多个这类问题只计一次。类型、参数个数、静态语义或相反条件等错误仍在 `errors` 中，不并入该窄口径无效数。

空任务目标召回率为 1；目标与预测都空时精确率为 1，非空任务但空预测时两率均为 0。`covered`、`missing`、`extra` 改为完整目标的逐条对照，错误原文也可在 extra／errors 中复查；保留独立的显式覆盖兼容字段。采用精确事实匹配，不额外做目标等价或蕴涵替换。

指标基于最终用于诊断的模型提案；先前解析失败的原始尝试仍在 calls 与 parse_retries 中。CSV 或报告中的 invalid=0 不能解读为从未产生错误，尤其不代表参数类型正确。

### 补全开销与放弃策略

`CompletionReport` 新增 `abandoned`、`abandon_reason`、`elapsed`、`processed_steps`、`deleted_steps`；pipeline 返回累计 `completion_elapsed`。补全过程执行以下规则：

1. 每次修补子搜索使用最多 **50,000 次扩展**和 **5 秒**时间预算，较先达到者生效；预算耗尽立即放弃整份模型方案，不再继续补齐任务目标。
2. 整个补全累计预算为 **20 秒**，跨规则反馈后的所有模型轮次共享。模型推理不在补全计时段内，不能每轮重新获得 20 秒。每次子搜索只取得最多 5 秒与全局剩余预算的较小值，处理步骤、重放和接纳修补计划也检查截止时间。
3. 处理了至少 **4 个原始模型步骤**且删除超过一半时，立即因质量过低放弃；恰好一半不触发。补出步骤不计入该比例，未处理步骤不伪装成删除。

触发后记录原因，保留已处理条目和部分计划供审计，但不再向模型反馈、也不使用任何 hint。最终调度仍从原任务初始状态、以原目标和原距离 cost 作独立最优 A* 搜索，预算仍为 20 万状态／60 秒。放弃的只是“是否继续修补和参考模型方案”，不会缩小最终搜索空间或牺牲最优性。全局计时及单次截止均记录真实观测值，不把时间舍入成虚假的零开销。

中文报告、计划 JSON、CSV 均记录放弃标记、原因和补全耗时。四类步骤计数来自已实际处理的条目，放弃时不必与模型原始步骤总数相等。实验新增严格耗时判定：每组 `total_elapsed <= none.total_elapsed + inference_elapsed + 30`，不使用额外容差；违反时不能只因 solved 就报告实验通过。
