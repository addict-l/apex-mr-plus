## 1. 根因：水平侧抓把腕部压到了底板高度

从 `m3_attempt_4/s1_reach_handover/compile_evidence.json` 的 r2（A）拒绝记录：前 10 个下降样本通过，之后 8 个种子全部被拒，原因是 `A_joint_5/link`（腕部）碰 `Baseplate`、`A_joint_2/link`、`A_joint_3/link`（上臂、前臂）碰 `Workbench`。

几何上：积木放在底板上时中心高 0.81 m；侧抓的工具 z **水平**，TCP 与腕部同高，腕部在 TCP 后方约 0.20 m，也就是悬在底板上方 **约 4 cm**（腕部连杆半径约 4–5 cm），前臂从肘部斜向下压向台面。B 在 `stock_r1` 取料能过，只是因为料垫在裸台面上（0.760 m）、腕部恰好在台面外侧，余量不到 1 cm，属于侥幸。任何放在底板上的目标位，水平侧抓都会这样失败，这不是种子或分支问题。

## 2. 修复：侧抓绑定加一个固定的向下俯仰角

### 2.1 `simbridge/frames.py`
- 新增常量 `SIDE_GRASP_PITCH = math.radians(45)`。`side_payload(block, arm)` 的工具姿态改为：先按现在的方式确定水平接近方向（A 从 +y、B 从 −y 接近，手指沿世界 x 闭合），再**绕工具 x 轴（手指闭合轴）把工具 z 向下转 θ**，使工具 z 从水平变为“指向积木、同时向下 45°”。TCP 仍在工具 z 反方向、距积木中心 `size_y/2 + 0.006` 处——所以 TCP 位于积木侧面外上方（水平外 0.054 m、上 0.054 m）。积木本身仍然水平放置，绑定中记录的是积木相对 TCP 的变换，取料、交接、放置全程不变。
- `handover_poses` 的偏航选择只用工具 z 的**水平投影**，逻辑不变；`handover_retreat` 仍沿 −工具 z 退 0.10 m（现在是斜向上、朝基座方向）。
- `approach_pose` 仍为目标上方 +0.10 m，下降仍为竖直直线。俯仰后手爪全部在积木顶面以上、侧面以外，竖直下降不会碰积木或垫。
- 几何核算（θ = 45°，腕部按 TCP 后方 0.20 m 估计）：A 放 `board_l1` 时腕部约在 z = 1.00 m，离底板 0.23 m；交接时两臂腕部到各自基座约 0.63 m，退让后仍约 0.63 m；B 取 `stock_r1` 腕部到基座约 0.65 m。都在 UR5 的舒适区。
- θ 允许的取值只有 45°、30°、60°。先用 45°；只有真实运行给出明确碰撞或超出可达的证据时才换，每次换都在 README 记录依据。不得为了过某一段而给不同动作用不同的 θ。
