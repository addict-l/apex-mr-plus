# v1.2.1 修订交接单

请在 `D:\APEX_MR_Plus\dualarm_skillnet\` 下继续工作。仍然遵守 `SPEC.md` 第 0 节的工作规则，以及 `HANDOFF_v1.2_LLM.md` 第 1 节的权限范围（本轮**不需要**再安装软件或下载模型）。不要修改 `SPEC.md`、`FIX_v1.1.md`、`HANDOFF_v1.2_LLM.md` 和本文件；本轮改动和说明写进 `README.md` 新增的“v1.2.1 修订”一节。

## 背景：v1.2 验收发现的问题

1. **测试与真实服务冲突**：`tests/test_ollama.py` 的模拟服务绑定 `127.0.0.1:11434`，与真实 Ollama 使用同一端口。Ollama 运行时，有 9 项测试报 `PermissionError: [WinError 10013]`。而 `OllamaDecomposer` 只接受 `127.0.0.1:11434`，测试无法换用其他端口。“服务未启动”类的测试在 Ollama 运行时也可能误连到真实服务。
2. **无法检验模型对自然语言的理解**：实际提示词里除了 `instruction`，还直接写了 `任务目标：free(A), free(B), at(red, board_l1)`。模型目标与任务目标的对比因此几乎必然一致，失去了意义。
3. **复杂任务上模型严重拖慢链路**：`s3a_cantilever` 不用模型时总耗时约 1.3 秒，用模型后为 323 秒（minimal）和 617 秒（with_capabilities）；`s3a_platform` 从 5.5 秒变为 137 秒和 57 秒。主要原因是：模型方案大部分不可行，补全的子搜索耗费大量时间，最后仍由独立搜索求解。
4. **下载残留**：`out/ollama_installer/` 中仍有约 1.8 GB 的安装包和分段文件。

## 本轮要完成的事

### 1. 测试与真实服务分开
- 模拟服务改为绑定 `127.0.0.1` 的**随机空闲端口**（端口号传 0，由系统分配）。
- `OllamaDecomposer` 的地址校验放宽为：**只允许 `http://127.0.0.1:<端口>` 或 `http://localhost:<端口>`**，端口可配置；默认仍为 `http://127.0.0.1:11434`。其他主机、https、带用户名密码、带路径的地址仍然拒绝，原有的拒绝测试保留并相应调整。
- “服务未启动”类的测试，改为先申请一个空闲端口再立即释放，然后连接这个端口，确保不会连到真实服务。
- 所有不依赖真实模型的测试，**不得访问 11434 端口**。

### 2. 新增“只给自然语言”的设置 `nl_only`
- `build_prompt` 新增 `mode="nl_only"`：包含任务指令、场景、技能清单和能力摘要，**不包含任何形式化目标**（不出现 `任务目标：` 及目标事实列表），也不包含默认目标的说明。提示词要求模型自己在 `goal` 中写出目标条件。
- 原有的 `minimal` 和 `with_capabilities` 保持不变（仍给形式化目标），用于对照。
- 目标对比改为与**完整目标**（任务文件的显式目标 + 默认目标）比较，记录：
  - `goal_recall`：完整目标中被模型目标覆盖的比例；
  - `goal_precision`：模型目标中属于完整目标的比例；
  - `goal_invalid`：模型目标中无法解析、谓词不存在或对象不存在的条数；
  - 逐条列出缺失和多余的目标事实。
- 模型目标仍然**不替代**任务文件的目标。

### 3. 限制补全开销
在 `complete` / pipeline 中加入两条放弃规则，触发时**不再修补模型方案**，直接进入独立搜索（不使用 hint），并在报告和实验数据中记录放弃原因：
- **单次补全子搜索上限**：扩展 5 万个状态或 5 秒，先到者为准；**整个补全过程上限** 20 秒。
- **方案质量过低**：已处理的模型步骤中，被删除的步数超过一半（且至少处理了 4 步）时，立即放弃。

放弃规则只影响“是否修补”，不能影响最终搜索的最优性。

### 4. 清理下载残留
删除 `out/ollama_installer/` 下的安装包和分段文件（`*.exe`、`*.bin`），保留日志、`download.cfg`、`parts.json` 和 `resume_single.py`。在 `ENV_SETUP.md` 末尾补一行说明清理时间和释放的空间。

### 5. 重跑实验
对 9 个任务运行四种设置：`none`、`minimal`、`with_capabilities`、`nl_only`。输出到新目录 `results/llm_v1_2_1/`，不覆盖 `results/llm_v1_2/`。实验表在原有指标基础上增加：是否放弃修补及原因、`goal_recall`、`goal_precision`、`goal_invalid`、补全耗时。

## 验收标准（全部满足才算完成）

1. **Ollama 运行时**和**Ollama 停止时**，分别运行完整测试集，都全部通过（真实模型测试在未设置 `SKILLNET_LIVE_MODEL=1` 时跳过）。在 README 中记录两次运行的结果。
2. 设置 `SKILLNET_LIVE_MODEL=1` 且 Ollama 运行时，真实模型集成测试通过。
3. 新增测试：`nl_only` 提示词中不出现任何形式化目标；地址校验接受本机任意端口、拒绝其他地址；两条放弃规则分别能被触发并正确记录；触发放弃后最终结果与 `none` 一致。
4. 实验 36 组（9 × 4）全部 `solved`，完成时间与 `none` 一致（误差不超过 1e-6）。
5. **耗时约束**：每组实验的完整链路耗时，不超过“`none` 的耗时 + 该组模型推理耗时 + 30 秒”。
6. `summary.md` 增加 `nl_only` 的目标理解结果（每个任务的召回率、精确率、无效条数）和放弃修补的统计，并给出与 v1.2 的耗时对比。
7. `out/ollama_installer/` 中不再有安装包和分段文件。
