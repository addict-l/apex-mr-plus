## 1. 根因：南北相向侧抓把腕部推到了 UR5 的可达边界

从 `m3_attempt_3/s1_reach_handover/compile_evidence.json` 读出的事实：

| 项 | 数值 |
|---|---|
| 交接点 `hand_mid` 世界坐标 | (0.00, 0.10, 0.972) |
| B 基座 | (0.70, 0.13, 0.783)，到交接点水平距离 **0.70 m** |
| 侧抓绑定 | B 从南面（−y）接近，工具 z 指向 +y，TCP 与积木中心的偏移 0.14/2 + 0.006 = **0.076 m** |
| B 在交接位的 TCP | (0.00, 0.024, 0.972) |
| 腕部中心 | 在 TCP 后方约 0.20 m（掌心到 TCP 0.071 + 法兰到掌心 + d6 0.082），即 y ≈ −0.18，到基座水平距离 ≈ **0.77 m** |
| 退让方向 | 沿 −工具 z = 世界 −y，再退 0.10 m 后腕部到基座 ≈ **0.82 m**，超过 UR5 上臂+前臂 0.817 m |

证据里 r5 的关节序列印证了这一点：肘关节 q3 从 0.611 单调降到 0.187（伸直），然后 IK 只剩下肩/肘翻折的另一分支，所以出现约 π 的跳变。**退让方向背离基座**，任何连续性阈值都救不了它。

A 臂是对称的：A 从北面接近、向北退让，同样背离 A 基座，只是 A 的退让段 r6 还没轮到编译。

## 2. 修复：交接时让积木绕 z 转到“两臂各从自己基座一侧接近”

不改抓取绑定（取料、交接、放置全程同一绑定，不重抓），只改**交接点处积木的偏航角**。积木在空中的朝向是自由的，规划层对 `hand_mid` 没有朝向要求。

### 2.1 `simbridge/frames.py`
- `handover_poses(block, location, giver, taker, giver_payload)`：交接点的积木位姿不再固定为单位四元数。在候选偏航 {0°, 90°, 180°, 270°} 中选一个，使 **giver 的退让方向（−工具 z 的水平投影）与“交接点 → giver 基座”的水平方向夹角最小**，同时 taker 的退让方向与“交接点 → taker 基座”夹角也要 ≤ 90°；两者冲突时以夹角之和最小为准。基座位置从 `workcell` 的臂配置读取（当前为 (±0.70, 0.13)），不要写死 90°。
- 当前布局下这会选出 90°：B 从东面（+x）接近、向 +x 退让，A 从西面接近、向 −x 退让。此时 B 的 TCP 在 (0.076, 0.10, 0.972)，腕部到基座约 0.41 m，退让后约 0.31 m，都在舒适区。
- 返回值增加 `yaw_rad` 与选择理由，写进该运动请求的 metadata，便于复查。
- 取料位和放置位的积木朝向**不变**（仍按料位/槽位的位姿），转动发生在 giver 持物转移到交接点的 `transit` 段和 taker 从交接点到放置接近位的 `transit` 段，这两段是 RRT 自由运动，无需额外处理。

### 2.2 `simbridge/primitives.py`
- 交接的两段 `linear` 退让继续用 `handover_retreat`（沿 −工具 z 退 0.10 m）。修复后退让方向朝向各自基座，不需要改退让距离。
- 若 2.1 修复后退让段仍因“接近基座、肘部折叠过紧”失败（表现为自碰撞或 IK 无解，而不是分支跳变），**按顺序**尝试且只允许这两项：① 退让距离改为 0.06 m；② 退让方向改为“−工具 z 与 +z 各一半”的斜向上。每改一项都要在 README 里记录依据，不得放宽 0.25 rad 连续性、2 mm/0.02 rad 直线证书和碰撞约束。

### 2.3 新增测试（不启动仿真器）

## 3. 本轮顺带修正的两处偏差

### 3.1 `runner.run` 缺少“用真实后端重新规划”一步
`HANDOFF_v1.3_SIM.md` 第 6.1 节要求：规划 → 建场景 → **用真实后端重新规划（含反馈回路）** → 编译 → 执行。当前 `runner.py` 直接从规划结果进入编译，编译失败即任务失败，`summary.feedback` 恒为空。这属于 M4 的内容，M3 阶段可以不接；但请在 M4 接入 `CoppeliaBackend` 时**把这一步放进 `run`**，使编译失败能回到 pipeline 加 cut / qualify 后重搜，而不是在 runner 里终止。验收标准 4 的“运动失败 → cut → 重搜 → 改走中转 → 执行成功”就依赖这一步。

### 3.2 旧任务的物理布局与目录尺寸冲突（M4 前必须解决）
README 已指出：`s2_tower`、`s3a_*` 的料位间距 0.10 m 小于砖宽 0.14 m 和料垫宽 0.18 m；`s3a_*` 的柱、梁、配重、临时台的 x/y 全部相同，物理上梁根本不悬出。这些任务文件是规划层的测试夹具，**不要修改它们**（241 项规划测试依赖其坐标和工时）。处理方式：
- 新建 `tasks/sim/` 目录，放物理一致的仿真版本：`s2_tower_sim.toml`、`s3a_cantilever_sim.toml`、`s3a_platform_sim.toml`。要求：任意两个料位/中转位/交接点的参考点水平间距 ≥ 0.20 m；料位到最近臂基座的水平距离在 0.30–0.65 m 之间；悬臂任务里柱槽位偏离梁中心，梁悬出端在柱外 ≥ 0.18 m，配重槽位在柱的另一侧，临时台槽位在悬出端正下方，`anchors`/`support_point`/`platform_for`/`needs_support_during` 语义与原任务一致。
- 规划层对这三个文件也要能求解（`run` 命令不带后端），并在 README 中记录它们的名义工时。
- 五个真实门控测试改为：`s1_parallel_place`、`s1_reach_handover`、`tasks/sim/` 下的三个。原三个旧任务保留给规划测试，不再要求它们在仿真中通过。
