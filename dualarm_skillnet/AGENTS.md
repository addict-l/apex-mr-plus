# 项目工作规则

## 决策与执行分工

每轮由侧对话分析上轮结果，决定是否修改、具体改法、验证步骤和停止条件，写成提示词交给用户。主对话只执行用户转交的本轮指令，返回实际结果和证据。每轮完成后暂停，等待用户转交下一轮方案。

- **测试轮**只用现有工具执行指定测试，保存实验数据、日志和报告。无论测试成功、失败或证据支持某项修改，都在本轮交回结果。测试结果本身不授权修改源码、测试脚本、参数或验收条件。
- **修改轮**须有单独指令，明确改动内容、范围和验收步骤。主对话只实施列明的修改和验证。侧对话不得在测试轮提示词中用“若验证成功就自行修改”等条件把决策权交给主对话。
- **遇到新问题**，主对话记录现象及证据，继续其余已授权且可独立执行的步骤。若现有工具或方案无法完成某一步，报告阻塞并保留现场。补写工具、改用其他方案、追加修复或启动新批次，均等待下一轮指令。

## Windows 后台仿真

除非用户明确要求交互窗口，仿真、测试、回放及其监督进程均在后台运行。逐层检查启动入口，包括每个场景新建的子进程。Python 启动 Windows 控制台程序时使用 `subprocess.CREATE_NO_WINDOW` 或已验证的无控制台启动方式。PowerShell 使用 `Start-Process` 时指定 `-WindowStyle Hidden`。将标准输出和错误写入本轮日志，保留既有的超时、退出码和子进程清理机制。

每次使用新启动入口，在首个实际用例开始时核对项目进程、日志进度及可见终端窗口。冻结的历史脚本如会弹窗，在本轮独立启动入口处理，保留历史产物。
